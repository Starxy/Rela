# Windows 实机验收

## 已自动验证

- 前端类型、lint、配置校验、Native 命令映射和演示服务。
- Rust 配置序列化与转义、密钥不回显、状态解析、DPAPI、Windows 参数引用、服务操作文件互斥。
- 两个 EasyTier 2.6.4 进程仅通过 loopback 连接：默认两个开关被加载，RPC 返回真实节点连接，错误密钥被拒绝，停止后 RPC 关闭。
- 上述隔离测试使用 no_tun，不修改系统网卡或路由，也不连接提供的公网节点。
- 原生窗口验证：点击最小化和关闭按钮后窗口隐藏，Rela 进程继续运行。托盘区域未暴露给当前自动化工具，图标点击恢复与菜单退出仍需手动验收。

## 待在独立测试机验证

请使用 Windows x64 测试机或可还原的虚拟机。以下项目尚未标记通过：

- [ ] 安装包安装到 Program Files，运行库完整。
- [ ] 普通用户启动 GUI，首次连接 UAC 同意后创建 RelaEasyTier 服务和 Rela 网卡。
- [ ] UAC 取消后状态仍正确，不显示已连接。
- [ ] 使用内置配置连接真实网络、取得 IP，并验证目标资源。
- [ ] 错误密钥、不可达节点、RPC 端口占用分别显示失败或等待状态。
- [ ] 修改配置保存后不立刻重启；保存并重连应用新参数。
- [ ] 断开停止服务；连续点击或多个 GUI 同时操作不产生多个服务实例。
- [ ] 最小化和关闭窗口后隐藏到托盘，点击图标或“打开 Rela”恢复原窗口。
- [ ] 托盘菜单“退出 Rela”结束 GUI，Core 仍运行；重新启动后能读取实际状态。
- [ ] 系统重启后当前手动启动策略有效，不意外自动连接。
- [ ] 原有 EasyTier GUI、服务、网卡不受影响。
- [ ] 非管理员无法读取或修改 ProgramData/Rela 的 Core 配置与引擎。
- [ ] 导出诊断不含网络密钥；机器其他用户无法解密 network.dat。
- [ ] 升级与卸载可正确停止/删除专用服务，无文件锁死；保留的本地配置符合预期。
- [ ] 增加实际校园网关及资源地址后，校验网关、延迟、路径类型和业务可达性。
