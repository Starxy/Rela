# 本体更新与恢复事务

此文记录 T35、T36、T38、T39 的实现边界。绿色版已接入文件事务、进程互斥、一次性助手、Core 延迟提交、新版启动握手和用户确认入口。安装版已串联独立非提权控制器、官方 updater、NSIS 前后确认、原用户配置事务和隐藏候选启动。两种形式的真实 GUI/UAC/两个连续签名版本升级均尚未验收，当前实现不能作为正式交付证据。

## 进程与操作互斥

更新必须先保留原进程句柄，同时核对 PID、创建时间和程序路径，再等待真正退出。关闭窗口仍是隐藏到托盘，不能当作程序退出。文件被其他副本占用时报告失败，不强制结束不属于本次更新的进程。

同一用户的安装版和绿色版通过 LocalAppData/Rela/coordination/update.lock 协调：网络控制持有共享许可，更新持有独占许可。文件句柄关闭或进程退出后操作系统释放锁，不使用持久化的“正在更新”布尔值替代锁。不同 Windows 用户的服务变更仍由受保护的 ProgramData 服务控制锁约束。

非提权 runner 已接入独占许可和精确进程等待。同配置实例锁位于配置目录之外，回退改名 data/config 时仍保持锁；配置、偏好、清单刷新和网络操作受进程内门禁保护，已有操作完成前不进入更新。

## 绿色版文件事务

文件事务在原 GUI 和配置写入进程退出后准备。目标目录必须已有 portable.txt，更新源必须来自通过包签名、摘要和 ZIP 校验的 PortableStage。暂存对象字段不可由调用者直接构造，消费前再次核对完整文件树与摘要；重新打开事务同样要求重新验证的包及匹配的事务编号。

`.rela-update` 保存 old、next、config-before 和事务日志。程序只替换固定程序/许可证清单及 checksums.json，不接收任意目标路径，不覆盖 portable.txt、日志、WebView 缓存或其他用户文件。data/config 采用有大小、数量和深度限制的完整快照，保留加密凭据及空目录。启动新版本之前预检已有文件占用，并为新旧程序、配置快照和替换临时文件预留空间。

| 日志状态   | 中断后的处理                                                  |
| ---------- | ------------------------------------------------------------- |
| Prepared   | 等待本次候选进程停止，恢复旧程序和配置，再回退 Core           |
| Committing | 提交决定已经持久化；核对新文件并继续提交 Core，不能再回退本体 |
| Committed  | 新版已提交，仅重试备份清理                                    |
| RolledBack | 旧版已恢复，仅重试备份清理                                    |

每个程序文件从保留的快照复制到临时文件，核对摘要并刷新到磁盘后原子替换。回退不消耗唯一旧快照，因此在任一文件边界中断后可以重试。配置恢复先保留候选版本生成的配置，再从旧快照重建；失败迁移数据最终保存在 `data/recovery/update-<事务编号>`，便于人工恢复。

提交决定必须在 Core 删除其备份前持久化。候选 GUI 隐藏启动，先验证本地设置、配置和缓存，再由已挂载的 React 界面请求启动确认。在收到最终提交指令前，窗口、托盘恢复、配置操作和自动清单刷新保持关闭；失败或通道断开退出候选程序。提交前失败回退；提交决定之后即使助手连接断开，也应继续完成提交。终态清理严格检查已知路径，拒绝删除意外文件，日志最后删除。清理失败不改变既有提交决定。

## Core 参与者

Core 准备阶段持有机器服务锁，使用当前受保护的已生效 TOML，保留此前的运行/停止状态；未安装服务时不因为软件升级而安装服务或发起连接。

准备完成后停留在 AwaitingApplication，保留完整旧引擎和配置备份。普通连接和恢复操作拒绝接管这笔事务。只有匹配事务编号的协调者可提交或回退；提交重新检查引擎摘要、配置摘要以及运行实例和版本。受保护的完成回执允许重复确认同一决定，并拒绝改成相反决定。

失去助手连接或超时本身不能决定回退，因为本体可能已经写入 Committing。控制器必须按持久化决定恢复。已接入独立的受限提权 Core worker：只接受准备、提交、回退；通信使用有大小/超时边界的回环 TCP、一次性随机口令、用途和进程身份校验。worker 使用经过验证的新版本暂存 EXE，并保留机器服务锁。此实现尚未实际触发 UAC 或操作本机服务。

## 助手与恢复入口

`.rela-update-control` 保存签名清单、原始签名 ZIP、候选目录、原版本 runner 和 DPAPI 控制记录。命令行仅带固定操作和事务编号，不允许前端传入包地址、目标路径、命令或凭据。每次恢复重新验证清单、ZIP 和候选文件；签名后的文件句柄阻止助手使用期间被替换。

普通启动在配置迁移前识别未完成事务：仍有对应 runner 时拒绝另开窗口；runner 已退出则重新握手并等待当前进程退出后恢复。提交前回退、提交决定后继续提交。控制记录保存终态以覆盖文件事务日志已清理但助手尚未退出的中断边界。完成后将控制目录原子归档为 `.rela-update-finished-<编号>`，暂时保留用于诊断；未完成下载及未成日志的快照也保留在独立准备目录，不能将它们误判为已完成升级。

## 验证范围

支持性测试使用真实临时文件及实际 Windows 文件占用，覆盖全部程序替换边界的错误和模拟进程丢失、重复恢复、配置迁移失败、提交清理中断、篡改和未知文件保留。进程测试启动隐藏的测试子进程，核对身份、退出等待和退出后的锁释放。

Core 服务行为和候选启动在事务测试中由受控参与者提供。这些测试不代替真实 GUI、SCM、UAC、TUN、两种安装形态及两个连续签名版本的升级验收；未完成的系统项目继续保留在 todo 和 Windows 验收文档中。

## 安装版接入中的行为约束

官方 tauri-plugin-updater 2.12.0 在启动 NSIS 后退出调用进程；install(bytes) 接受调用者提供的字节，因此必须先通过 Rela 的独立包签名/摘要/版本验证。其 on_before_exit 在启动安装器之前调用，UAC 取消仍可能随后发生，不能在此回调里不可逆提交 Core。

原 NSIS 钩子会直接删除共享服务，官方默认同名进程检查还可能终止其他副本。现在覆盖该检查，只针对目标文件进行有界占用/权限探测；普通卸载和升级保留共享服务，显式清理工具单独确认。安装器前后确认、用户配置快照、本体/Core 提交、非提权控制器、候选启动及恢复调度已串联；钩子编译和支持性测试不能替代真实升级验收。

## 官方安装器适配层

`updates/installer.rs` 使用固定版本 tauri-plugin-updater 2.12.0。它重新验证用户确认的签名软件清单、渠道、最低可升级版本和准确版本，然后在本机随机端口建立一次性、随机路径、5 秒超时的临时 HTTP 响应。响应只包含这份已验证清单派生的版本、说明、日期和 windows-x86_64-nsis 安装包信息。官方 updater 读取该响应后，应用再次比较结果。

此适配不增加另一份可变的线上 JSON。资源、软件清单和安装包的外部请求继续要求 HTTPS 与现有主机白名单；官方插件没有固定外部入口，不使用代理或重定向。tauri.conf.json 的 dangerousInsecureTransportProtocol 只为上述本机适配器启用；原生适配器拒绝非空 endpoints、不安全 TLS、降级、未绑定版本的签名或额外安装参数。前端没有任何 updater 插件权限，只能走应用自身的业务命令。

安装包通过 Rela 有界下载器暂存，安装前重新打开，验证长度、SHA-256、minisign 全局签名与 trusted comment 中唯一的 version 字段，并持有禁止写入/删除的文件句柄。官方 install(bytes) 需要完整内存缓冲，因此安装版限制为 512 MiB；Portable ZIP 仍使用原来的 2 GiB 上限。拒绝签名版本缺失、不一致或重复，不依赖不受信任的注释。

官方 NSIS 重启被关闭，由独立控制器负责隐藏候选启动和最终提交。GUI 确认绑定原生已验签版本；安装器只在独立 launcher 中调用，参数只包含已验证请求路径和末尾的固定安装目录 /D，拒绝继承任意安装参数。未绑定事务的适配器只能验证，launch 会直接拒绝。适配测试运行真实官方插件与本机 HTTP，但使用 MockRuntime 和不可执行的合成包，不执行 NSIS、不触发 UAC、不访问 SCM。

## 安装版文件与系统信息恢复层

`updates/installed.rs` 已实现 perMachine 文件事务，并通过 NSIS worker 接入非提权控制器和 GUI 入口。它只接受重新验证的签名 PortableStage，用其中与安装版共有的程序和许可证文件核对 NSIS 输出；README、绿色版标记、data 和其他用户文件不属于安装版替换槽位。旧主程序与卸载器必须存在，旧安装位置、版本、程序名称及发布者必须匹配受支持布局。

`.rela-installed-update` 保存不可变旧文件、待安装文件和日志，并备份 NSIS 当前写入的 14 个固定注册表值及两个公共快捷方式。注册表键和快捷方式路径由代码固定，日志不能指定其他路径或额外命令。Windows 适配器检查所有者、写权限、硬链接与重解析点，并持有安装目录、固定子目录及祖先目录的句柄以阻止换名。恢复后的程序文件允许普通用户读取和执行，写入仍限系统与管理员。

| 状态                   | 恢复规则                                                                   |
| ---------------------- | -------------------------------------------------------------------------- |
| Prepared               | 安装尚未确认；等待安装器和候选进程停止后可重复恢复旧文件、注册表和快捷方式 |
| Installed              | 完整输出已匹配签名文件，系统信息及新卸载器已记录；提交决定前仍可回退       |
| Committing             | 提交决定已落盘；只能继续完成 Core 与本体提交                               |
| Committed / RolledBack | 复验终态，只清理已知且摘要匹配的备份；未知内容和占用文件保留               |

开始清理前，先以写穿方式保存独立的 `.rela-installed-result-<编号>.json` 受保护完成记录。它保留完整终态绑定，在日志已删除或完成通知丢失后仍可复验并重复清理；与现存日志矛盾的记录被拒绝。完成记录暂时保留，不能据此删除后来新建但未写入日志的准备目录。

12 项支持性测试覆盖逐文件、逐注册表值和快捷方式回退的错误与模拟进程退出、真实文件占用、提交决定保存失败、部分清理、完成通知丢失、篡改及非预期文件保留。权限测试仅解析内存中的 Windows 安全描述符，不修改实际系统权限。

## 安装版用户配置与安装器参与者

`updates/configuration.rs` 使用发起 GUI 的实际配置路径，不能在管理员进程中重新解析 AppData。原 GUI 退出且非提权控制器取得同配置实例锁后，备份完整配置、缓存及当前用户 DPAPI 凭据；日志由当前用户 DPAPI 保护。回退先保留候选迁移结果，再复制旧快照并原子换回。提交后禁止回退，终态清理和归档可重复；失败迁移数据与终态记录保留在配置目录旁的恢复目录。9 项测试覆盖配置存在/缺失、迁移删除配置、中断、占用、篡改及凭据保留。

`updates/nsis_worker.rs` 提供 PRE、POST 与恢复入口。请求绑定签名清单摘要、原版本、目标目录、runner 摘要和精确进程身份，三个通信角色各自使用一次性口令。新助手重新验证清单、ZIP、全部候选文件及自身摘要；PRE/POST 还验证实际 NSIS 进程的签名、版本与父子关系，不能仅相信命令行 PID 或进程名。机器记录和签名资产先在独立受保护目录准备完整，再原子发布为 `.rela-installed-control`。

PRE 必须收到备份许可、完成本体备份并收到允许安装命令，最后持久化授权标志，才能成功返回给 NSIS。未持久化授权且尚无完整本体日志的准备中断，仅在原程序摘要和旧安装信息仍匹配时重建备份，残留内容原样另存。POST 验证实际安装输出后准备 Core；Core 准备失败不能进入提交。提交先保存本体 Committing，再提交 Core；提交失败重试同一决定。回退先恢复本体，再回退 Core；最终清理要求两者状态一致并由原用户控制器确认配置已处理。10 项支持性测试覆盖这些状态与失败边界，SCM 使用受控参与者。

NSIS 钩子从安装包自身提取助手，持有临时目录和程序文件句柄直到 POST 结束，不执行目标安装目录或请求路径提供的助手。编译器固定为已检查的 NSIS 3.11，其受限插件目录创建包含竞争条件修复，见 [官方变更记录](https://github.com/NSIS-Dev/nsis/blob/v311/Docs/src/history.but)。脚本编译通过不能替代管理员权限下的实际运行验收。

首次手动安装成功后创建受保护的 `.rela-installed-running.lock`，普通 GUI 使用只读共享锁，PRE 取得独占锁。启动在打开配置存储之前检查机器未完成事务；手动安装和卸载也拒绝跨过该事务。终态机器控制目录原子归档，完成确认丢失后可按原事务重新打开，但不能跳过后来出现的新事务。文件锁测试使用真实只读 Windows 句柄，没有修改安装目录 ACL。

## 安装版控制器与恢复入口

`updates/installed_controller` 保持原用户权限。它同时保存已验签安装包和 Portable 配套包；后者用于逐文件核对安装输出及提供同版本恢复助手。更新界面显示两包合计下载量。控制目录为实际配置目录旁的 `.rela-installed-user-<编号>`，包含原 runner、签名源、暂存候选与当前用户 DPAPI 控制记录；独立的配置路径绑定指针最后发布。原 GUI 只在精确身份验证的助手确认接管后退出。

控制器取得同配置实例锁后先备份配置，再启动独立 launcher。官方 updater 成功启动 NSIS 后即退出 launcher，控制器继续运行。PRE/POST 通信分别验证助手真实文件摘要、签名安装器及进程父子关系；控制器先持久化安装器身份及 Active 状态，才发送 PRE 准备许可。启动器退出本身从不代表安装完成。UAC 启动失败会结束等待；尚未授权 PRE 的中断可恢复原配置而不再次请求提权。

POST 确认文件、元数据和 Core 准备后，普通用户控制器启动隐藏候选。候选在配置存储初始化前认证控制器，等待实例锁；前端就绪后再次校验本地存储。候选身份先落盘再接受握手，避免启动速度造成误判。提交顺序为受保护本体/Core 决定、用户配置、机器 Finalize、准确的助手和安装器退出、终态记录、窗口释放。配置恢复失败不能清除机器备份。

普通启动在迁移配置前检查指针。旧控制器退出后，重新启动保留的 runner；所有已知候选、launcher、hook 和 NSIS 必须真正退出，磁盘记录的 PID 仅等待、不强杀。恢复 worker 也要先完成认证和 Prepare 许可才能重建备份；机器未开始状态需要在独占锁下确认全部记录不存在、旧程序摘要和安装信息一致。已保存 Committing 的机器事务只能继续提交，通信断开或确认丢失不能改变决定。

若主程序文件不能启动，可在发起用户的恢复控制目录运行 `Recover-Rela.cmd`；该入口只恢复已有的密封事务，不发起新升级。成功后，候选或恢复的旧程序等待 runner 退出，将用户控制目录归档为 `.rela-installed-user-<编号>-finished` 并移除指针。归档与失败迁移内容暂时保留；指针仍存在但活跃记录损坏时，不能借旧归档绕过它。

控制器新增的测试使用真实临时文件、DPAPI、文件锁和临时签名，覆盖双包重验、路径/角色绑定、配置目录换名、损坏/归档冲突、配置提交回退与 Finalize 确认丢失。真实 NSIS/UAC/Core、headless Tauri launcher、不同管理员授权、多用户、目录 ACL 与两个连续版本验收均未完成；尤其需要验证发起用户能检查提权助手的实际镜像，不能用支持性测试替代该权限验证。
