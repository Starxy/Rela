# Rela 产品与技术设计说明

版本：2026-09-30。当前决策采用 Secure Mode credential 与受保护的 TOML，覆盖最初的设备注册与 Config Server 方案。本轮交付范围见[分发与配置约定](distribution-config-decisions.md)，实现与验收状态分别见 [架构](architecture.md) 和 [Windows 验收](windows-validation.md)。

## 1. 产品定位

Rela 是实验室成员访问校园 GPU、NAS、SSH 和内部 Web 服务的轻量 Windows 客户端。用户通过一个连接开关查看网络是否可用，通过二级弹窗访问资源、设置和诊断。

首期平台为 Windows x64。界面采用 400 × 560 小窗口，保持简单，避免暴露无关的网络工程参数。

## 2. 当前范围

只开发客户端，直接使用已经部署的 EasyTier 网络。无需开发服务端、邀请码注册 API、Config Server 或独立后台 Agent。

当前 network/peer 由 main 根目录 resources.json 提供，构建中不保留实验室线路兜底。已发布清单和本机初始开关对应以下运行参数：

```toml
[network_identity]
network_name = "lab201"
# credential 在运行时写入 secure_mode，不提供 network_secret 或 peer_public_key。

[[peer]]
uri = "tcp://47.93.55.228:12010"

[flags]
private_mode = true
disable_p2p = true
```

UI 允许修改名称、credential、一个或多个节点以及两个开关。校园网关 IPv4 可选，用于网关和延迟检测。使用 DHCP 分配虚拟地址。凭据和公共节点不能确定校园网关地址，不据此推断网关或资源。

首次无缓存时显示等待获取，缺少网络参数或凭据时禁止连接；用户显式填写有效本地线路也可连接。保存不立即中断连接；“保存并重连”使用新配置重启。客户端不内置主密码或 credential。首次连接需要导入管理员签发的凭据，更换网络时必须重新匹配凭据。

本期只按单个 lab201 网络设计，允许用户在本机覆盖 network/peer；备用 peer 用于从另一条线路接入同一网络，不开发多网络列表或迁移向导。已有的网络名与凭据绑定校验继续保留。当前不要求提供校园网关、中继角色或版本信息。

用户修改 network 或 peer 会停止整个线上清单的自动获取，并在重启后保持该状态。手动点击“更新线上配置”即允许覆盖本地 network/peer 和资源；完整校验并保存成功后恢复自动刷新，失败则保留本地配置。private_mode、disable_p2p、gateway_ip 和设备偏好不由远程下发。软件更新检查不受本地覆盖影响。软件本体只检测新版、提醒手动更新并打开 GitHub Release 页面；客户端不下载、安装或回滚软件。

## 3. 技术方案

| 层 | 技术与职责 |
| --- | --- |
| 界面 | React、TypeScript、Vite；连接、设置、资源、诊断 |
| 桌面 | Tauri 2.11.x；窗口与受限业务命令 |
| Native | Rust；配置、DPAPI、服务控制、状态转换、诊断 |
| 网络 | 固定 EasyTier Core 2.7.0-0a783c8e 开发版；TUN、路由、加密、节点重连 |
| 后台运行 | Windows 专用服务 RelaEasyTier |

Rela Rust 后端直接管理 Core。首次部署、引擎或运行配置变化通过同一 Rela 程序的临时提权入口执行，不增加长期运行的自研服务。GUI 保持普通权限；首次授权后，同一 Windows 用户可直接启停已批准的服务，日常连接、断开和重连不重复弹 UAC。更换引擎、网络参数、credential 或设备名称时重新授权。

Core 以独立系统服务运行，GUI 退出不主动断开。最小化或关闭窗口时隐藏到系统托盘；点击图标或选择“打开 Rela”恢复原窗口，“退出 Rela”结束 GUI，保留 Core 连接。当前服务手动启动，自动连接、开机启动明确不在本期交付范围，失败自动恢复尚未实现。

## 4. 网络引擎分发

构建前获取固定提交的官方 Windows x64 开发构建并校验归档及文件 SHA-256。来源与校验值记录在 config/easytier-version.json，Actions 产物有保留期限，需另行长期归档。安装包携带 Core、CLI 及所需运行库。程序启动服务前验证资产哈希，复制到受保护的 ProgramData 目录，使用固定名称安装服务。

同时提供 Portable ZIP 免安装版。完整解压后运行，界面配置、诊断和缓存保存在同目录 data 下。首次连接需要系统授权并创建上述专用服务，之后复用当前用户已批准的启停权限；退出界面保持连接，包内提供管理员服务清理工具。安装版与便携版共用网络服务，不应同时控制连接。WebView2 由系统提供，跨机器使用时须恢复默认或重新填写当前用户加密的网络配置。

RPC 固定在 127.0.0.1:35888，实例名 rela，TUN 名称 Rela。Core 禁止外部监听；RPC 配置回环白名单。目前无独立的 RPC 调用者认证。

不得启动或停止用户已有的其他 EasyTier 实例。同名服务路径冲突或管理端口冲突时应明确报错。多个 Rela 实例的服务操作必须互斥。

完整安装、升级和卸载须在干净测试机验证。第三方运行库的许可说明随包提供；T45 已记录 Packet.dll 的内部授权，公开发布包的实际分发范围仍需与授权一致，见 [第三方说明](../THIRD-PARTY-NOTICES.md)。

## 5. 首页与连接状态

首页展示连接开关、连接状态、校园网关、延迟、连接方式、资源入口、诊断和详情入口；发现新版时显示手动下载提示。

状态分为引擎不可用、未连接、连接中、已连接及错误。Core 运行仅表示进程就绪；“已连接”要求节点连接成功、分配了虚拟 IP，并且系统中对应虚拟网卡已持有该地址。

网关是否可达独立检测，未知时显示横线。资源可用数量只统计真实探测结果，不从节点列表推测。

## 6. 设置

网络页包含：

- 网络名称。
- credential 粘贴输入；已保存凭据不回显，留空保留同网络值，支持更换与断开后的清除。
- 连接节点列表，每行一个。
- 私有模式、禁用 P2P，默认开启。
- 可选网关检测地址。
- 保存、保存并重连、恢复默认。

常规页包含设备名称、软件检查和稳定/测试渠道选择。开机启动和自动连接本期不交付，现有入口保持禁用。输入校验由前端即时反馈，Native 再次校验，不能依赖前端作为安全边界。

管理员在应用外使用 EasyTier CLI 手动签发 credential，并自行指导组员。应用复用现有填写、更换和清除入口；文件导入、丢失处理、过期/撤销管理和自动续期不作为本期交付条件。认证失败仍须如实提示。

## 7. 存储和隐私

构建仅嵌入分发入口、公钥和通用参数，不读取本地 JSON、DPAPI 凭据文件或 RELA_NETWORK_SECRET。凭据不进入程序、启动参数、普通错误消息或诊断摘要。

公共配置使用原子状态指针，credential 独立使用当前用户的 Windows DPAPI 加密。Core 所需明文 TOML 保存在仅系统和管理员可读写的服务目录，使用 credential 私钥和推导的自身公钥。管理员、系统以及可调用本机未认证 RPC 的进程仍在当前安全边界之外。

前端没有任意 shell 或文件系统调用权限。Native 不接受任意命令或程序路径。服务资产和配置写入使用固定路径、ACL、哈希与原子替换。

## 8. 诊断

当前检查真实的引擎状态、虚拟 IP、节点连接和可选网关。导出包含版本、状态和结构化检查项，不收集 Core 原始配置或未脱敏日志。

后续增加资源端口、DNS、默认路由及网卡冲突检测时，应区分未知、探测失败和确定故障。ICMP 失败不能代表 SSH 或 Web 一定不可用。

## 9. 实验室资源

根目录 resources.json 管理 SSH、Web、NAS 入口，包含名称、地址、类型、描述和探测端口；可用性由客户端真实探测，不由清单指定。首份 Spark SSH `192.168.200.10:22` 已接入，不预设用户名。该资源仅作占位，网络建成后由管理员维护；未连接时显示未检测。

资源打开仅传递清单 ID，Native 校验目标后用参数数组调用系统工具。不得拼接 shell 指令或接受任意 URL 作为资源打开参数。

2. 已实现普通 JSON 资源配置、本地覆盖与手动更新；继续在真实网络验证端口探测与快捷入口。

凭据由管理员手动签发，Rela 负责填写保存和使用。后续通过公开 GitHub 仓库分别发布软件更新清单与资源清单，network、peer、resources 从资源清单获取，凭据单独交付，成员无需 GitHub 令牌；具体依赖顺序见 todo.md。

## 11. 第一阶段验收

- 新安装包获取并校验根目录默认网络配置，首次必须填写获授权的 credential；无缓存或凭据时不能误报可连接。
- 默认私有模式和禁用 P2P 确实传给 Core。
- UI 修改可保存，credential 不回显，重连后生效，清除与恢复默认会要求重新导入凭据。
- 真实获得虚拟地址，状态与 TUN、节点连接一致。
- 断开停止专用服务，重连应用保存配置，关闭 GUI 不断网。
- 原有 EasyTier 实例不受影响，取消授权、端口冲突和错误凭据不会显示假成功。
- 诊断摘要不包含密钥，权限和安装生命周期通过独立测试。

单元测试、浏览器演示和 no_tun 隔离连接通过，仅证明对应层级，不能替代上述系统验收。
