# 分发与配置约定

确认日期：2026-09-30。本文记录用户确定的产品范围；当前实现、验收状态与执行顺序见 [todo.md](../todo.md)，已实现接口见 [protocol.md](protocol.md)。本文不维护另一套待办。

## 分发与默认数据

- 使用公开仓库 [Starxy/Rela](https://github.com/Starxy/Rela)。客户端获取公开清单、用户通过浏览器下载发布包均不要求提供 GitHub 账号或令牌；发布端权限另行管理。
- 资源与网络配置直接维护 `main` 根目录的普通 JSON；软件更新继续使用独立签名清单、版本比较、缓存和稳定/测试渠道。软件发布链路按当前 todo 收尾。
- 默认网络名为 `lab201`，默认节点为 `tcp://47.93.55.228:12010`。首期按一个实验室网络设计，备用 peer 用于经另一条线路接入同一网络。
- 第一份资源清单仅需包含 `Spark`：SSH 主机 `192.168.200.10`、端口 `22`。它是占位资源，不代表当前可达；网络建成后由管理员维护资源清单。不预设 SSH 用户名或登录密码。
- [resources.json](../resources.json) 是唯一生产资源与网络配置。客户端读取 `https://raw.githubusercontent.com/Starxy/Rela/refs/heads/main/resources.json`，管理员直接编辑并提交该文件即可生效。[resources.example.json](../config/resources.example.json) 仅为测试样本。
- 当前不要求补充校园网关、中继拓扑、角色或版本清单；网关未配置时显示“未设置”，节点延迟与路由独立读取，不据此阻止连接。

## 远程字段与本机字段

| 数据                                        | 来源与修改规则                                            |
| ------------------------------------------- | --------------------------------------------------------- |
| `network`、`peer`                           | 远程提供默认值，用户可在本机覆盖网络名和节点              |
| `resources`                                 | 管理员维护远程资源清单，客户端探测可用性                  |
| `private_mode`、`disable_p2p`、`gateway_ip` | 仅由本机设置管理，不由远程清单下发或覆盖                  |
| 设备名称                                    | 本机偏好                                                  |
| credential                                  | 管理员在应用外手动签发，用户在应用内填写，本机 DPAPI 保存 |

资源配置使用 `schema_version`、整数 `version`、`network`、`peer`、`resources`。`version` 仅作展示，内容更新不需要提高版本号或签名；客户端采用固定地址的最新有效内容。软件版本独立。配置不包含凭据、设备偏好或本机网络开关；资源可用性来自实际探测，不作为远程事实发布。

`private_mode` 和 `disable_p2p` 维持现有本机初始值 `true`，`gateway_ip` 初始为空。用户修改这些本机字段不会关闭线上清单的自动刷新。

## 自动获取与本地覆盖

- 使用线上默认 network/peer 时，启动后在后台静默读取根目录 resources.json，不阻塞窗口；手动更新读取同一地址。
- 用户保存不同于默认值的 network 或 peer 后，进入本地覆盖状态。整个线上资源/网络清单停止自动获取，包括其中的 resources；已有有效缓存仍可使用。
- 本地覆盖状态需要持久化，重启应用后不能重新自动拉取；保存操作还须防止已经发出的自动请求在返回后覆盖本地修改。
- 用户手动点击“更新线上配置”即允许覆盖本地 network/peer 和资源列表。完整校验成功后保存线上值，清除本地覆盖状态并恢复自动刷新；失败则保留本地修改及覆盖状态。
- 手动更新只覆盖清单管理的字段，不覆盖 private_mode、disable_p2p、gateway_ip、设备名称或 credential。network 名称真正改变时仍遵循已有凭据绑定校验，不自动复用不匹配的旧凭据。
- 软件版本检查独立进行，不因本地覆盖网络配置而停止。发现新版仅提示手动更新并打开 GitHub Release 下载页面；不在应用内下载安装或回滚软件。
- 资源自动或手动获取失败、格式无效时保留上次有效缓存与本机配置；软件验签失败保留其可信缓存。不因获取失败中断已有连接。
- 网络参数仍在下次连接或用户点击“保存并重连”时生效，刷新清单不自动重连。

本期不开发多网络列表、账号切换或远程跨网络迁移向导。已有的网络名与凭据绑定校验继续保留：只修改 peer 不要求重新填写凭据；真正修改 network 名称时仍需同时提交匹配凭据或清除原凭据。这是输入校验，不增加多网络管理流程。

## 凭据与交付范围

管理员手动使用 EasyTier CLI 签发 credential，并自行教组员使用。Rela 本期仅负责输入、保存、更换、清除与连接使用；现有填写入口可复用。不开发凭据签发服务、自动续期、丢失处理、过期/撤销管理，也不要求文件导入界面作为交付条件。连接认证失败仍须如实提示，不能显示已连接。

真实 credential 只作为私密本机输入处理，不写入源码、清单样本、文档、发布包、启动参数或诊断输出。

开机启动和自动连接明确不在当前交付范围。Windows 服务、UAC、真实 TUN、安装版和绿色版手动更新验收仍需完成；Spark 占位资源的实际访问在网络就绪后验收。现网的凭据生命周期和其他节点调查不再作为资源功能开发的前置依赖。

## 当前实现边界

资源格式验证、公开获取、缓存、本地覆盖和资源界面均已接入；旧签名资源缓存保留离线读取兼容。Spark 仍是占位，实际访问待网络就绪后验收；后续工作只按当前 todo 推进。

构建已移除内置 network/peer 默认值。线上默认模式无有效清单时等待获取；用户明确填写并保存的有效本地 network/peer 配合 credential 可以用于手动连接，不被资源缓存缺失阻止。未获取资源时显示空资源列表，不伪造 Spark 可达状态。
