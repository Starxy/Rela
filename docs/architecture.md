# 架构与初始化范围

## 分层

```text
React / TypeScript
    │ 业务接口，禁止传递 network_secret、CLI 参数、路由配置
    ▼
Tauri Commands / Rust Native
    │ 内置 EasyTierCore 模块：生命周期管理、RPC 状态读取
    ▼
EasyTier Core 2.6.4（待验证和集成）
```

前端使用统一 `RelaService`。桌面端始终调用 Native；只有 Vite 开发模式或显式设置 `VITE_RELA_PREVIEW=true` 的浏览器构建才加载演示服务。界面采用 400 × 560 小窗口，以连接开关和关键状态为主，其他功能通过二级弹窗访问，不展示开发模式提示和说明性文案。浏览器预览不打开真实资源地址、不修改系统设置。

桌面端目前能保存设备显示名称、返回版本信息、导出结构化离线诊断摘要。连接命令直接调用 Rela 进程内的 `EasyTierCore` 模块；该模块目前返回 `core_unavailable`，尚未启动 Core 或建立 RPC 连接。占位模块不能作为功能完成依据。

## 直接管理 Core

Core 生命周期和 RPC 接入放在 `src-tauri/src/easytier`；凭据、资源探测、日志和系统集成由 Rela 的 Rust 后端负责。前端只调用 Tauri 业务命令。

Windows 后台运行计划采用 Core 系统服务，由操作系统负责开机启动和进程失败后的恢复，Rela 通过系统服务接口和 Core 本机 RPC 直接管理。关闭或更新界面应保持 Core 连接；退出与断开是独立操作。服务安装、普通用户控制权限和目标版本的 RPC 能力仍需验证。

GUI 保持普通用户权限，安装和更新 Core 服务时按需提权。TUN、路由等网络操作由具备所需权限的 Core 执行。服务控制只允许管理 Rela 安装的 Core 实例，RPC 的调用授权须单独验证。Rela 运行时负责资源健康检查，退出后由 Core 继续维护网络连接。

默认安装包只包含普通用户桌面壳。`tauri.sidecar.conf.json` 预留固定版本 Core 打包入口，不负责启动 Core 或安装服务。真实服务安装将由明确的安装流程处理提权。

## 安全边界

- 前端不获得 shell 或文件系统插件权限。CSP 不允许加载远程页面、脚本和 iframe。
- 资源打开接口只接收管理员资源列表中的 ID。后续实现需校验资源类型、协议、地址和用户名，再用参数数组调用系统工具，禁止拼接 shell 命令。
- EasyTier RPC 只能绑定 `127.0.0.1`。不能用“仅本机监听”代替调用者身份验证。
- Core 服务的安装路径、配置和可执行文件须限制写入权限；普通用户只获得必要的服务控制权限，不能借此替换服务程序或传入任意启动参数。
- Device Credential 必须留在系统安全存储；不得出现在 React 状态、`localStorage`、普通配置文件、错误消息和诊断导出中。
- 当前诊断使用业务字段白名单导出，不读取原始日志。后续添加日志包前，必须覆盖凭据、URL token、机器标识和用户路径的脱敏测试。
- 未获取状态时不保留旧的“已连接”显示；Core 正在运行也不能等同于网关或实验资源可用。

## 工程约定

- Node.js 22.12+、npm，提交 `package-lock.json`。Rust 工作区提交 `Cargo.lock`。
- 最低 Rust 版本为 1.88；Cargo 优先解析与此版本兼容的依赖。升级最低版本和依赖需要一起验证。
- Tauri Rust crate 和前端 API 固定在同一 `2.11.x` 次版本，升级时需同步；CLI 也采用 `2.11.x`。
- TypeScript 与 Rust 当前手工维护对应模型。协议变化需同步修改 `src/types.ts`、`crates/rela-protocol` 和接口文档，并增加行为测试；扩大协议前宜引入自动生成。
- Windows 是首个验证平台。其他平台保留模块边界，不声称已有服务实现或发布支持。
- EasyTier 版本随 Rela 统一验证升级，禁止运行时直接下载 `latest`。
- `docs/产品与技术设计说明.md` 与当前产品和架构决策同步维护。
